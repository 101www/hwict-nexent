# 低资源场景本体构建与知识版本更新方案

本文件区分已实现能力与后续计划。当前领域为高血压临床诊疗与基层慢病管理，三份全文中的自动抽取均待核验。

## 已实现的构建方式

本体实体类型、关系类型及端点约束保存在`ontology/ontology.json`；术语及别名在`lexicon.json`。临床、管理、数值关系按分源规则抽取，代码见`pipeline/build_graph.py`及各extractor。

目前主要由人工根据三份全文制定词表和正则规则，程序完成匹配、规范名归并、证据偏移定位和结构检查。`ontology/extraction_prompt.md`只是候选抽取的提示词设计，不代表已调用LLM自动构建本体。

图谱中的关系保留原文、文件、物理页、章节、条件、规则ID、pending与未校准confidence。缺端点或未解释的片段保留为候选；置信分不是医学正确率。

## 新增的知识更新闭环

入口为`tools/evolve_graph.py`及本地审核工作台，详细操作见[知识更新审核与版本回放](D:/JavaProject/huawei/nexent-cognitive-agent/docs/10-知识更新审核与版本回放.md)。

```text
基线完整快照＋新增/修改资料
→ 合并来源，全量重建候选图谱
→ 按ID比较新增、修改、未再出现记录
→ 生成待审提案和原文证据
→ 本体约束、证据字符区间及结构校验
→ 填写审核署名和理由：暂缓／驳回／批准
→ 独立发布动作，保存版本与审核记录
→ Java明确加载快照进行查询回归
→ 必要时回滚指针，保留所有后续版本
```

审核批准的是工程发布，不会将自动记录改成医学已审核。真实人工审核尚未开展；演示测试身份为`automated_test`。

| 机制 | 当前实现 |
|---|---|
| 来源触发 | 用户在工作台选择新的重排文本，或CLI显式提交路径；不是自动监听目录 |
| 差异提案 | 节点、关系、阈值、规则、原文块、候选按ID比较；差异不自动裁决成真冲突 |
| 低资源审核 | 可先看变化与证据，再暂缓、驳回或批准；尚未验证节省人工时间 |
| 未知类型 | 对候选中的未定义实体/关系类型提出待核验建议，并阻止违反本体约束的发布 |
| 本体版本 | 对比类型、关系定义及约束；本体内容改变必须增加版本号，经重新提交和校验 |
| 发布绑定 | 审核绑定完整提案、候选及快照哈希；阻止审核后变化、过期基线、未批准发布 |
| 完整快照 | 保存原始文本、图谱、本体、规则、代码、来源哈希和审核事件 |
| 旧记录保留 | 旧图快照和evolution_retained保留完整旧记录，不只保存被移除ID |
| 回滚 | 改变本仓库当前版本指针，不删除新版本；Java需明确重启加载 |

## 当前演示及边界

本轮演示为已有真实资料的历史入库回放：“仅管理标准”到“管理标准＋基层指南”，再回滚。真实Java MCP两跳方案路径数量为0→2→0。这验证知识和证据可更新、可追溯、可回滚；没有发生真实本体定义变化，不能声称已经展示自主本体进化。

本体变更机制用明确标记的合成生命周期夹具验证，不注入真实医学图谱。程序当前不会自动理解未知概念并学出新抽取规则；本体候选的含义、规范名及端点仍须人工确认。

## 与行业标准的对应

当前关系通过来源文件、实际版本、条款、物理页和原文映射到管理标准或指南；同名不同版本的引用会保留不匹配状态。例如标准指向的2021基层指南不能由已入库2025版自动替代。

`ontology/standards_mapping.csv`和`review_log.csv`仍是早期占位模板，不得作为已完成的标准对齐表或真实人工审核样本。真实运行事件保存在版本仓库的`events/`及`state.json`，后续需整理规范对齐表并由人工核验。
