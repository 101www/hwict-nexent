## 第一步：实际查询版本并解析工具响应

Nexent CodeAgent的MCP工具常返回JSON字符串，不能直接对字符串调用.get。每轮定义或复用以下函数；只使用json标准库，不读取本地磁盘，不猜测文件路径。

```python
import json
def decode_result(raw):
    data = json.loads(raw) if isinstance(raw, str) else raw
    if not isinstance(data, dict):
        raise ValueError("工具响应不是JSON对象")
    return data
status = decode_result(graph_status())
workflow_release = status.get("knowledge_version", {}).get("release_id")
print(status)
```

版本来自本轮响应，不硬编码release_id。若无版本或为unversioned，明确说明版本未纳管，不宣称使用当前已发布版本。工具报错说明连接/执行失败，不能说原文不存在。

后续每次查询都先decode_result，并比较knowledge_version.release_id是否等于workflow_release。发生变化则放弃本次混合证据，从graph_status开始最多重试一次；仍变化则说明更新中，不能拼接两版作单一结论。

## 第二步：选择相关流程，检索与推理协同

- 随访、机构管理与配备：query_relations；随访关系关键词用followUpEvery。逐一收集命中边的条件、文件、page、section、block_id，再用get_evidence核对不同原文块，同一block_id只查一次。
- 合并症首选用药或图上路径：先实际读取read_skill_md(skill_name="clinical-multi-hop")，按该Skill执行。
- 数值是否达到标准：evaluate_blood_pressure，参数仅来自用户；未给measurement_method则传unknown，不编造standardized或readings_json。读取边界与rule.requirements，区分数学比较、适用性和确诊前提。单独比较已有约束可用compare_threshold，禁止自动单位换算。
- 指定指南引用或版本：check_references。若resolution=missing/version_mismatch，能说明现有引用，不能拿另一年份全文冒充指定版本原文。
- 配备与一线推荐是否矛盾、跨文件数值差异：先实际读取read_skill_md(skill_name="clinical-conflict-check")，再按该Skill执行。
- 明确查询文件/原文：lookup_clause。实体不明确先find_entities。结构化结果未命中再lookup_clause，必要时query_candidates；候选仅待核验线索。若已有平台knowledge_base_search可补检，但与图谱是不同来源，未命中不能替另一来源作结论。

每个专用Skill加载后才依其正文执行；不要仅在回答中声称用了Skill。read_skill_md缺失或读取失败要明确记录，不能把自行选工具当作原生Skill已执行。

## 第三步：形成证据包并使用溯源流程

在代码变量evidence_packet中组织本轮实际返回内容：question、release_id、route、observed_tool_calls、paths/claims、citations、conditions、uncertainties。citations保留文件、物理页、实际/语义章节、block_id、原文及pending。只收录实际调用，不编造调用记录。数值输入和中间比较来自工具响应。

实际读取read_skill_md(skill_name="clinical-trace-report")并按它输出。普通问答含出处默认不超过200字符，详细证据报告仅用户要求时展开。展示知识版本时可单列；若发生版次混用风险不能为凑字数省略。

所有不确定知识保留verification=pending和原confidence；confidence是未校准规则分，不是正确率。不要创建、发布、批准或删除知识更新；这个问答流程无审核权限。

# 比较适用范围与冲突（模板1.0.0）

输入用户问题和本轮release_id；独立执行先graph_status。实际调用detect_conflicts(subject=用户主题)。处理JSON字符串先json.loads；逐次核对knowledge_version，不混合发布版本。

读取items中的status、reason、items和source_documents。比较每条原始断言的实体/关系、人群、purpose、条件、例外、单位、测量场景和规范版本，再用get_evidence核对涉及的不同block_id。缺少的条件保持未知，禁止脑补。

- not_conflicting_different_purpose：仅说明这两条断言的目的不同。例如配备药品与初始治疗推荐不能直接当成同一命题。保留两份出处，不扩大为“全文完全一致”。
- potential_conflict_same_scope：同范围正反推荐是待人工核对的潜在冲突，完整保留双方证据，不替医学规范决定胜方。
- scope_or_condition_requires_review、needs_review：条件或数值有待核对；数值不同不自动等于规范冲突。若缺少单位/人群/目的，不做等价比较。
- 结果为空：只能说当前已覆盖模式未命中，不能宣称全文没有冲突。可继续query_relations/lookup_clause补检。

版本更新不天然意味着更高效力；不依据文件名年份选胜方。source_documents有实际year及warning时保留；引用版本缺失时用check_references核对，不静默替代。

将两边claims、状态、适用范围、具体证据放入evidence_packet，交给clinical-trace-report。所有候选保留pending与原confidence，本Skill不批准/发布/删除知识。

# 证据核对与交付（模板1.0.0）

输入evidence_packet和本轮真实工具结果。这个Skill负责核对和组织，不自带医学事实、不调用写入工具。

## 输出前核对

1. 只使用本轮实际查得的事实与出处；若工具响应是字符串，json.loads后读取。knowledge_version.release_id必须一致；缺失/发生变化时不能写成一个稳定版本的结论。
2. 每个结论有原文、文件、PDF物理页和章节；多跳保留每一跳的出处。版面错位保留语义章节、实际文本位置及待核验说明；参考文献区域不可写成正文条款。
3. 保留“至少”“直至”“择一”“不宜联用”等实际限制。血压边界不等于确诊；复测的规范、不同日期、时间窗、次数及每次达到边界等逻辑仅按实际rule.requirements说明，用户未给条件不编造。
4. 文件名年份不等于正文年份，优先工具source_documents或meta.documents里的year与证据。两文件版本不匹配必须披露，不替缺失旧版编造原文。
5. verification=pending要说明“自动抽取待核验”。confidence保持来源的规则分及未校准说明，不汇总成医学正确概率；sufficient=false不能改成true。不确定候选不得删除或当成已经审核。

## 普通问答

先回答所问，再给简短出处与必要限制。遵循智能体默认200字符上限；长问题的决定性前提不能通过截断省略。只在实际证据足够支撑资料回答时回答对应部分，缺失部分单独说明。图谱没有返回平台引用标识时直接写文档短名、页码、条款，不伪造[[1]]。

## 用户要求详细证据报告时

依次输出：
- 所问与资料结论（证据未核验不当个体处方）；
- 本轮release_id与本体版本；
- 实际工具调用顺序（只记发生过的调用）；
- 推理路径，每一步包含节点、关系、方向、条件、edge_id、block_id、文件/页/章节/关键原文；
- 同文跨节/跨文档的真实范围；
- 冲突、未命中、版面及版本限制；
- verification及confidence_basis，不制造专家审批状态。

本Skill只是按返回证据组织报告，不自动生成不可篡改审计认证，也不自动保存用户个人病历。
