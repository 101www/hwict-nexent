# 有条件的多跳取证（模板1.0.0）

输入：用户原问题、总流程本轮release_id（若独立执行，先graph_status）。工具JSON字符串必须json.loads后读取；所有响应版本须一致。

## 专用两跳

对“合并糖尿病的高血压患者首选哪类药”这种问题：实际调用resolve_regimen(population="高血压合并糖尿病患者")，其他人群用工具可识别的完整名称，不能把糖尿病答案套用到未知合并症。

读取items中的paths、components、selection和restrictions等实际存在字段。每条path的steps[].edge必须保留id、headId、tailId、relation、regimen_group、条件和原文出处。确认两条边属于同一个非空regimen_group，再解释人群←首选方案→成分。按components的one_of解读择一，不能把可替代类别变成联用方案。

读取每一跳的supporting_evidence及原文block_id，实际get_evidence核对首选句、定义句和限制句；同一块去重。首选句若section_status=needs_layout_review，同时保留semantic_section、实际section/page，面向用户说明“版面待核验”。不要只引用类别定义冒充人群首选证据。

## 通用路径

未知实体先find_entities。traverse_relations从实际实体开始，最多3跳；查看steps的forward、边本身方向、条件与跳数。路径连通仅表示证据连通，不能由此自动传递药物适应证、禁忌或处方。没有合法可组合路径就报告未找到这类结构化证据，必要时回到原文查找，不强凑两跳。

## 交付给溯源流程

在evidence_packet保留路径和每一跳出处，按路径实际文件去重计数。文件数1且章节不同称“同文跨节两跳”，文件数至少2才称“跨文档路径”；不能把全文入库3份说成每次推理跨了3份。

保留verification=pending、confidence原值和confidence_basis。未核验的两跳结果不能变成个体化处方。最后交给clinical-trace-report；不在Skill中预填药物结论或页码。

# 证据核对与交付（模板1.0.0）

输入evidence_packet和本轮真实工具结果。这个Skill负责核对和组织，不自带医学事实、不调用写入工具。

## 输出前核对

1. 只使用本轮实际查得的事实与出处；若工具响应是字符串，json.loads后读取。knowledge_version.release_id必须一致；缺失/发生变化时不能写成一个稳定版本的结论。
2. 每个结论有原文、文件、PDF物理页和章节；多跳保留每一跳的出处。版面错位保留语义章节、实际文本位置及待核验说明；参考文献区域不可写成正文条款。
3. 保留“至少”“直至”“择一”“不宜联用”等实际限制。血压边界不等于确诊；复测的规范、不同日期、时间窗、次数及每次达到边界等逻辑仅按实际rule.requirements说明，用户未给条件不编造。
4. 文件名年份不等于正文年份，优先工具source_documents或meta.documents里的year与证据。两文件版本不匹配必须披露，不替缺失旧版编造原文。
5. verification=pending要说明“自动抽取待核验”。confidence保持来源的规则分及未校准说明，不汇总成医学正确概率；sufficient=false不能改成true。不确定候选不得删除或当成已经审核。

## 普通问答

先回答所问，再给简短出处与必要限制。遵循智能体默认200字符上限；长问题的决定性前提不能通过截断省略。只在实际证据足够支撑资料回答时回答对应部分，缺失部分单独说明。图谱没有返回平台引用标识时直接写文档短名、页码、条款，不伪造[[1]]。

## 用户要求详细证据报告时

依次输出：
- 所问与资料结论（证据未核验不当个体处方）；
- 本轮release_id与本体版本；
- 实际工具调用顺序（只记发生过的调用）；
- 推理路径，每一步包含节点、关系、方向、条件、edge_id、block_id、文件/页/章节/关键原文；
- 同文跨节/跨文档的真实范围；
- 冲突、未命中、版面及版本限制；
- verification及confidence_basis，不制造专家审批状态。

本Skill只是按返回证据组织报告，不自动生成不可篡改审计认证，也不自动保存用户个人病历。
