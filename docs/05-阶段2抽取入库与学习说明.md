# 阶段 2：多文档抽取入库与学习说明

> 历史基线说明：本文记录 v0.2 的实现和统计。后续 v0.3 已补充三份全文药物规则、pending/confidence 和候选保留机制；当前行为以 `06-待核验保留与全文药物规则.md`、构建报告和代码为准。下文数字保留作为迭代记录。

本轮完成的是本地文本到图谱的构建和离线查询。没有调用大模型，也没有更改已部署的 Nexent。Java MCP 的 GraphRepository 目前仍使用演示数据，尚未读取本轮生成的 graph.json。

## 1. 已完成的工作

| 工作 | 实现与理由 |
|---|---|
| 多文档构建 | build_graph.py 接收多个文件；相同实体合并，不同文件的断言与证据分别保存。默认使用三份 raw 重排全文。 |
| 编号标题解析 | 支持 1、1.2、8.4.2、A.1；正文跨页时保留当前标题，同时记录新的 PDF 物理页。 |
| 原文定位 | 每条新抽取证据包含 file、page、section、block_id、start、end、evidence；偏移相对该证据块 raw 字段，左闭右开。 |
| 词表和本体 | 补充机构、设备、管理行为、达标状态、条件条款和章节证据块。 |
| 管理关系 | 应配备、宜配备、随访频率、长期随访、健康教育、转诊条件候选和跨文档引用。 |
| 规则隔离 | 旧摘要的 4.1 和标准全文的 4.1 含义不同，旧药物规则只用于旧摘要，避免节号相同就误套规则。 |
| 数值差异 | 不再把同一指标出现不同数字直接标成真冲突；需要核对场景和适用条件。 |

规则匹配时临时忽略排版空白，但证据返回未经改写的原文。没有恢复表格的勾选列，也没有修改原始文本。

## 2. 实际构建结果

三份文件得到 166 个证据块、248 个节点、904 条边。边中包含 705 条来源标注和 166 条文档包含关系，因此不能把 904 当成医疗业务规则的数量。

本轮业务关系包括：应配备 14 条、宜配备 2 条、随访频率 4 条、长期随访 1 条、健康教育 1 条、转诊条件候选 5 条、文件引用 6 条。转诊条件保留原段落并标记 needs_review，不能直接执行自动处置。

可供离线查询的数值约束是两份文件分别记录的随访间隔，共 4 条。另有 20 条诊疗数值候选保存在 threshold_candidates 中，因表格、测量时段和人群尚未完整核验，不进入决策阈值集合。

已确认冲突为 0，当前可比较约束的跨文档待核对差异也为 0。这不表示三份全文完全没有冲突，只表示当前覆盖范围没有确认冲突。

## 3. 两处需要人工核验的版本问题

1. 文件名为“中国高血压临床实践指南2025版”的文本，第一页显示《中华心血管病杂志》2024 年 9 月第 52 卷第 9 期。构建报告保留原文件名，记录正文刊期 2024，并发出核验提示；没有自行重命名文件。
2. WS/T 872—2025 的参考文献列出了 2021 年基层指南，而当前入库的基层指南是 2025 版。标准中的四处“参见”均记录为 version_mismatch，年份判断的参考文献原文也一并保存。是否可以采用更新版补充解释，需要人工确认，不能自动认定版本一致。

另外两处引用来自基层指南，分别涉及《手册》和糖尿病管理指南；对应文件没有入库，记录为 missing。

引用目标文件存在，也只代表找到了文件，尚不代表已经找到能回答问题的具体条款。因此文件匹配成功后，仍需检索和核读原文。

## 4. 自己运行，观察图谱在做什么

在 PowerShell 进入项目目录：

```powershell
Set-Location 'D:\JavaProject\huawei\nexent-cognitive-agent'
python pipeline/build_graph.py
python tools/query_graph.py relations 随访
python tools/query_graph.py references WS-T872
python tools/query_graph.py conflicts
```

`relations 随访` 会展示这样的记录：

```text
血压达标患者 --followUpEvery--> 随访
出处：标准，PDF 第 5 页，8.3.2.1
原文：血压达标者：每 3 个月至少随访 1 次。

血压达标患者 --followUpEvery--> 随访
出处：基层指南，PDF 第 13 页，8.1
原文：血压达标患者，至少每 3 个月随访 1 次……
```

同一人群节点可以关联两份文件的证据。后续 MCP 工具将这些记录返回给大模型，大模型才有依据解释“要求是什么、出自哪里”。本轮没有完成 MCP 接入。

模拟“只加载标准”：

```powershell
python pipeline/build_graph.py --doc data/raw/WS-T872-2025_重排.txt --out data/processed/standard_only_graph.json
python tools/query_graph.py references WS-T872 --graph data/processed/standard_only_graph.json
```

这时四处引用的状态应是 missing。系统可以说明标准引用了什么，并引用标准本身已经写出的内容；缺少目标指南的细节应明确说明，不能凭模型记忆补成有依据的答案。

再次运行默认构建会更新主 graph.json，不受 standard_only_graph.json 影响。

## 5. 你同步做的学习任务

打开 data/raw/WS-T872-2025_重排.txt，先读设备、随访和转诊条款。自己写三个希望系统回答的问题，每个问题再记下：

- 你认为答案在哪个条款、哪一页？
- 只看标准够不够，还需要哪份文件？
- 什么信息缺失时，系统应该说明无法确认？

最后试着用自己的话回答：只有标准、没有基层指南，系统能确认什么，还不能确认什么？你的这份记录将用于后面的问答验收，不需要先懂所有代码。
